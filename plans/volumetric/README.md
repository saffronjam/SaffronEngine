# Volumetric & height fog (analytic height fog, froxel volumetrics, local fog volumes & aerial perspective)

**Status:** COMPLETED

The scene renders unbounded lit radiance into `ViewTarget.offscreen` and the Hillaire sky paints a physically-based backdrop behind it, but nothing fills the space *between* the camera and geometry: there is no participating medium anywhere in the engine, so the air is a perfect vacuum, distant surfaces read at full contrast, and a shaft of light through a doorway leaves no visible beam. The sky's transmittance and sky-view LUTs (`engine/crates/rendering/src/ibl.rs`) shade the horizon but never touch scene geometry as haze. This planset adds a **fog subsystem** — the cold atmosphere that fills a room and the red sun-shaft that scatters through it — inserted into the post chain on the linear-HDR `color` target, *before* the bloom pyramid and the tonemap/grade compute pass. It ships in two unified backends: a closed-form analytic exponential height/distance fog that is always-on and needs no new render-graph primitive, and a frustum-aligned froxel volumetric stage (Wronski-2014 inject/integrate + Hillaire-2015 energy-conserving integration) that reuses the entire clustered-light cull and every shadow family to produce lit, shadowed, temporally-stable god-rays — the analytic term is the strict base medium the froxel grid injects, never a second effect applied twice.

## Why

- **No fog of any kind exists; the atmosphere shades only the sky, never the scene.** `EnvSource::Atmosphere` bakes transmittance/multiscatter/sky-view LUTs and `submit_sky` paints them onto the background (`engine/crates/rendering/src/ibl.rs`, sky-view + transmittance LUTs; `engine/crates/assets/src/render_scene.rs`, `submit_sky`) → scene geometry receives no distance haze, no beam scattering, and no aerial blue-shift, so a lit interior and a sunset vista both read as if the air were empty.
- **The linear-HDR canvas and its composite seam are already in place and unoccupied.** The per-view scene target is `ViewTarget.offscreen` (`OFFSCREEN_COLOR_FORMAT = R16G16B16A16_SFLOAT`, `COLOR_ATTACHMENT|SAMPLED|STORAGE`) and the depth buffer is D32 with the `SAMPLED` usage and DEPTH aspect the composite needs (`engine/crates/rendering/src/view_target.rs`, `ViewTarget`) → fog belongs in the gap between the sky pass and `add_bloom_pass`/`add_tonemap_pass` (`engine/crates/rendering/src/renderer.rs`, final-post block), operating on unbounded radiance so distant emitters are fogged *before* they bloom — and today that seam holds no medium.
- **The clustered froxel light-cull, all four shadow families, and the TAA jitter already exist to be reused.** The per-cluster light lists and punctual SSBO are exposed as `cluster_buffer_with_size`/`light_list_buffer` on a fixed 16×9×24 exponential-Z grid, and ReSTIR already binds them into a standalone compute set (`engine/crates/rendering/src/lighting.rs`, `CLUSTER_GRID_X/Y/Z`, `cluster_buffer_with_size`; `engine/crates/rendering/src/restir.rs`) with directional/spot PCF, point cubes, and the TLAS all bound in the light set → volumetric in-scatter can reuse the whole direct-light + shadow rig verbatim.
- **But the light-eval helpers are file-private and there is no phase function in the mesh path.** `clusterIndexFor`, `distanceAttenuation`, `punctual`, `pcfShadow`, `pointShadow`, and `rayQueryShadow` are private to `engine/assets/shaders/lighting.slang` and hard-decorated to the mesh descriptor sets, and Henyey-Greenstein exists *only* in the atmosphere path (`engine/assets/shaders/atmos_skyview.slang`, `hgPhase`) → a compute fog pass cannot `import lighting` and call them as-is, so the helpers must be promoted to a public resource-parameterized shared module (the `giprobe` module is the template) and gain a phase term.
- **No fog shader, component, command, or DTO exists — and the render graph cannot make a 3D scratch volume.** There is no `height_fog.slang`/`fog_inject.slang`, no `FogSettings`/`FogVolume`, no `set-fog`, no `SetFogParams`, and no `submit_fog` on the `SceneRenderer` trait; and the transient pool is strictly 2D — `ImageDesc` carries a `vk::Extent2D` and `Image::new` hardcodes `TYPE_2D` + `depth: 1` (`engine/crates/rendering/src/resources.rs`, `ImageDesc`, `Image::new`; `engine/crates/rendering/src/transient.rs`, `acquire_image`) → the froxel stage implies a net-new authoring surface *plus* the one real infra gap, a 3D transient image and a 3D compute dispatch.

## Design stance (grounded in current engine practice)

The stages are built the modern, technically-correct way — the Wronski/Hillaire froxel pipeline unified with a closed-form analytic base — not the cheaper legacy shapes (a screen-space radial-blur god-ray, or a bright-pass "light shaft" post filter). There is one fog authoring surface with two backends selected by a mode flag, and the analytic term is a strict subset of the froxel path so the two never double-count.

**Analytic exponential height & distance fog — closed-form, always-on, no new graph primitive.** The base layer is UE's exponential height fog / iquilezles "Better Fog": reconstruct world position from scene depth, integrate the exponential-in-height density along the view ray in closed form (`opticalDepth = FogDensity · exp2(-HeightFalloff·Δh) · lineInt · max(RayLength − StartDistance, 0)`, with the numerically-critical Taylor fallback `lineInt ≈ ln2 − ½ln2²·F` for near-horizontal rays), clamp with `MaxOpacity`, and composite `scene·T + inscatter·(1−T)` plus a directional sun lobe `pow(saturate(dot(viewDir,−sunDir)·0.5+0.5), DirExponent)`. Inscatter is tinted by sampling the existing sky-view LUT (`ibl.rs`) so fog reddens toward the sun for free, and a summed second layer gives a thin ground haze under a broader layer. This is a single fullscreen compute pass over depth — it reuses no new render-graph capability, is the far-field fallback for every later phase, and retires the classic screen-space god-ray outright: there is no additive light-shaft path.

**Froxel volumetric fog — Wronski-2014 inject/integrate, Hillaire-2015 energy-conserving.** A frustum-aligned rgba16f 3D grid (160×90×128 high) with the *same* exponential-Z slice distribution the cluster cull already uses maps each froxel to its containing 16×9×24 cluster via `clusterIndexFor` and reads that cluster's light list — the exact ReSTIR reuse pattern. Injection accumulates `radiance · attenuation · shadow · hgPhase(g) · sigma_s` over the sun (cascade/spot PCF, point cube, optional inline RT ray-query for crisp shafts), plus IBL/atmosphere ambient and emissive; integration marches front-to-back with the energy-conserving analytic slice `S_int = (S − S·exp(−σd)) / max(σ, ε)` that removes Wronski's high-density banding. God-rays and volumetric shadows emerge free from shadowed in-scatter — no screen-space godray pass. This is the *destination*, and it is not offered beside a cheaper radial-blur approximation. The one real infra gap it forces is a **3D transient image** (the pool is 2D-only today) and a **3D compute dispatch** (`add_compute_pass` hardcodes `groups_z = 1`) — Phase 2 builds both against the working `Image3D` + `import_image_3d` precedent used by the Global-SDF albedo cache (`engine/crates/rendering/src/global_sdf.rs`).

**Aerial perspective — Hillaire-2020, sharing the froxel infra and one transmittance ledger.** Long-range planetary Rayleigh/Mie scattering fills a small separate 32³ volume ray-marched from the same atmosphere LUTs, on the same exponential-Z depth mapping and the same 3D-transient infra, composited as an *independent* multiplied medium so near fog, mid haze, and far atmosphere read as one continuous whole with no double-darkening. This applies aerial perspective to scene geometry, which the sky pass does not do today.

> **Scene shading → linear-HDR `color` → { analytic height fog (closed form) ⟺ froxel inject → integrate } + aerial-perspective volume → single fog composite on one transmittance ledger → bloom → tonemap/grade → present.** The analytic density and the froxel grid share one authoring surface and one `(inscatter.rgb, transmittance.a)` convention; only the backend and the far-field composition branch — `T_total = T_froxel · T_aerial · T_height`, `L_out = scene·T_total + inScatter_froxel + T_froxel·inScatter_aerial`.

## Goal

- **Scene-wide fog is scene state, driven by one command.** A `FogSettings` block on `SceneEnvironment` (mirroring `AtmosphereSettings`), round-tripped through `environment_to_json`/`environment_from_json`, edited by a single `set-fog` merge command modeled on `set-atmosphere` — the only command for its state, scriptable from `sa` with no per-command CLI code, surfaced back through `EnvironmentDto`. It is *not* a `RenderSettings` field the way bloom is.
- **Analytic height fog is a complete, self-contained subsystem.** A `height_fog.slang` compute pass over scene depth with the directional sun lobe and sky-view-LUT-tinted inscatter, composited into `color` before bloom via `SceneRenderer::submit_fog` — no new render-graph primitive, the always-on base and the far-field fallback.
- **Froxel volumetrics is a real render-graph subsystem.** `fog_inject.slang` + `fog_integrate.slang` compute passes over a 3D transient froxel volume, reusing `cluster_buffer_with_size`/`light_list_buffer` + all shadow families + a new public `hgPhase`, driven by a 3D dispatch after the light-cull pass and composited by the same fog stage — the two backends selected by `fog.mode` with no double-counting.
- **Local fog is a placeable component folded into the same grid.** A `FogVolume` hecs component (box/sphere, mirroring `ReflectionProbe`) injected during the *same* Phase-3 density evaluation, so local volumes are lit, shadowed, reprojected, and integrated by the identical stages — no second pass, no special path — placed via an `AddEntityPreset::FogVolume` and edited through the existing generic `set-component-field`.
- **No parallel fog path survives.** `set-fog` and the `FogVolume` component are the sole write paths; analytic mode is a strict subset of volumetric mode (its height density becomes the froxel base medium), so switching modes replaces the backend rather than layering a second effect — the NO-LEGACY unification lands in the same change that adds the froxel path.

The chain: Phase 1 (analytic height fog) stands alone and ships the whole authoring surface — `FogSettings`, `set-fog`, panel, docs — while needing no new graph capability, so it lands the always-on base immediately. Phase 2 also stands alone: it builds the sole infra gap (3D transient images + 3D dispatch + the grid module + the shared-module refactor) with a debug fill and *no* visual change, decoupling the risky plumbing from any rendering. Phase 3 is the NO-LEGACY cutover — it unifies the two backends under `fog.mode` so the analytic closed form stops being a standalone effect and becomes the froxel grid's injected base medium in the same change, with one transmittance ledger and no double-counting. Phases 4 and 5 refine the froxel path (temporal stability + per-light control; placeable local volumes), each riding the Phase-3 stages with no new pass. Phase 6 extends the same 3D infra to reconcile fog with the existing Hillaire sky.

## Future (unscheduled)

- **Volumetric clouds / cloud layers.** A raymarched cloud volume (Nubis-style density erosion) reuses the froxel 3D-noise + phase + transmittance infra this planset builds, but belongs to the sky/atmosphere planset and needs a cloud-shape authoring model and a much longer march budget — the seam (3D noise sampling, HG phase, the shared ledger) is left clean here but the cloud infra is not built.
- **Order-independent overlapping fog volumes.** Godot's atomic-packed signed-integer froxel buffer makes many overlapping `FogVolume`s (including negative/subtractive density) order-independent; Phase 5 ships the simpler summed loop over a small volume list, which is correct for a handful of volumes — the atomic model is the end state when counts grow but is deliberately deferred.
- **A dedicated fog-froxel light cull.** Phase 3 reads the coarse 16×9×24 cluster's light list via `clusterIndexFor`; a finer fog-specific cull (culling lights directly into the 160×90×128 fog grid) is the higher-fidelity option if the coarse per-cluster list proves inadequate for in-scatter, and is left unbuilt.
- **Sparse / imported density fields.** OpenVDB / sparse-volume-texture-backed heterogeneous density (UE Sparse Volume Textures) replaces the procedural-noise + analytic-slab authoring rather than sitting beside it, and needs an import + sparse-sampling path this planset does not build.

## Ground rules

- **One write path per setting.** `set-fog` is the sole command for scene-wide fog and the `FogVolume` component the sole local surface; never a second fog command, never a fog knob smuggled onto `set-environment`/`set-atmosphere`, never a duplicate composite pass.
- **The analytic term never double-counts the froxel path.** When `fog.mode = volumetric`, the same height density is injected as the froxel base medium instead of applied a second time; the analytic pass, the froxel integration volume, and the aerial-perspective volume all use one `(inscatter.rgb, transmittance.a)` convention and compose on one transmittance ledger.
- **Fog is scene state, not render settings.** Scene-wide fog lives on `SceneEnvironment` and round-trips in the project `environment` block; local fog rides the component serde — neither is a `RenderSettings` field. This mirrors the atmosphere, which is authored per-scene like the sky.
- **One schema.** DTOs live once in `dto.rs`; the hand-authored `EnvironmentDto`/`FogSettingsDto` schema in `schema.rs` + `component_block.ts`/`environment_dto.ts` is the single source, and `@saffron/protocol` (`editor/src/protocol/sa-types.ts`) is regenerated by `xtask gen-protocol` and never hand-edited. Every new DTO is registered across *all* tripwire lists (`command.rs` `COMMANDS`/`COMMAND_FIXTURES`/`DTO_TYPE_NAMES`/`scene_domain`, `codegen.rs`, `tests/inventory.rs`, `tests/schema_fragments.rs`) in one change — the build refuses otherwise.
- **Each phase ends green.** `just engine` + `just prepare-for-commit` (format + clippy `-D warnings`), a headless boot with a validation-clean log (`just run-engine-headless`) on a real fixture, an `sa set-fog` / `sa add-entity --preset fog-volume` probe that changes the frame, `bun run check` in `editor/` where a wire type changed, `just e2e`, and the `docs/content/` fog concept page + its hub `_index.md` row updated when the concept changes.

Detail lives in the phase files; this page is the index.
