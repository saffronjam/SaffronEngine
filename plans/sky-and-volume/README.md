# Dynamic sky, time-of-day, and volumetric clouds

**Status:** COMPLETED

The Hillaire sky LUT chain already paints a physically-based backdrop and feeds the env cube + IBL, and the fog planset already applies aerial perspective to scene geometry through a 32³ Hillaire froxel on a shared `(inscatter, transmittance)` ledger — but the sky is *frozen* and *empty*. Every sun move re-bakes the whole chain (LUTs → env cube → mips → irradiance → prefilter → BRDF) synchronously behind `device.wait_idle`, so time-of-day would stall the GPU each change; the "Sun" directional light is an authored color decoupled from the atmosphere it is drawn against; the diffuse ambient is a 32² irradiance cube and DDGI/voxel-GI ambient is a flat scene color, neither following the sun; and there are no clouds to sit in the atmosphere the froxel already tints. This planset makes the sky **dynamic** and **populates** it: an amortized re-bake path with sun/moon key lights read from the Transmittance LUT (Phase 1); a real-time sky-light re-capture that projects SH diffuse per frame and reconverges the prefiltered specular time-sliced/async, retinting GI (Phase 2); an ephemeris + artist-curve time-of-day driver with a physically-based night sky (Phase 3); then a decoupled cloud track — Nubis-style shape authoring (Phase 4), an energy-conserving lit raymarch with quarter-res temporal reconstruction (Phase 5), and integration that reconciles clouds with the *existing* aerial-perspective and fog ledgers, casts one density-integrated cloud shadow map into scene + fog, and animates by a shared wind field (Phase 6). It does **not** re-plan the base sky LUTs, does **not** rebuild aerial perspective (already shipped) or the froxel/3D-transient/TAA infra (already shipped) — clouds reconcile with them on one transmittance ledger, never a second AP volume and never a double-darkening composite.

## Why

- **The Hillaire sky is physically based but frozen.** Every sun move arms a full synchronous re-bake (`Ibl::should_rebake` → `fire_rebake` → `bake(false)` behind `device.wait_idle`, `engine/crates/rendering/src/ibl.rs`) → a time-of-day cycle would stall the GPU on every change, so the sky, key light, and sky-light IBL cannot animate at all.
- **The sun is decoupled from the atmosphere it is drawn against.** It is just the first `DirectionalLight` with an authored color — `drive_env_bake` sets `sun_dir = -light_dir` but never derives the light *color* from the Transmittance LUT (`engine/crates/assets/src/render_scene.rs`) → sunsets show the sky disc and the lit scene reddening/dimming by different amounts (the tell-tale decoupled-hack look), and there is no moon key light at all.
- **Ambient and GI never follow the sun.** Diffuse ambient is a 32² irradiance cube (`ibl_irradiance.slang`) and DDGI/voxel-GI ambient is a flat scene color (`ddgi_sky = environment.ambient_color * ambient_intensity`, `render_scene.rs`), neither derived from the baked atmosphere → reflections, ambient tint, and indirect bounce drift out of agreement with a moving sun and never follow time-of-day.
- **The atmosphere the froxel already tints has nothing sitting in it.** Aerial perspective already tints scene geometry (the 32³ `AerialPerspective` froxel on the shared `(inscatter, transmittance)` ledger in `height_fog.slang`), but there are no clouds to sit in that atmosphere → the sky reads as an empty dome, distant haze has nothing to shade, and the biggest AAA-look jump per unit of effort is unbuilt.
- **The infrastructure a cloud path needs is already paid for and unused.** The froxel-fog stage, 3D transient images + 3D compute dispatch, motion vectors + TAA history, and the one `(inscatter.rgb, transmittance.a)` ledger convention all exist and are unused by any sky/cloud path (`froxel_fog.rs`, `transient.rs::acquire_image_3d`, `view_target.rs`, `height_fog.slang`) → the expensive infrastructure a cloud raymarch and a cloud-shadow-to-fog coupling need is already there, but no cloud shape, lighting, shadow map, or ledger fold consumes it.

## Design stance (grounded in current engine practice)

The sky is made dynamic and populated the modern, technically-correct way — an amortized cost-asymmetric re-bake, one transmittance source of truth for every celestial light, and Nubis-style energy-conserving clouds reconciled onto the *existing* atmosphere ledger — not the cheaper legacy shapes (a synchronous full re-bake beside a static path, a hand-authored sunset color curve, a second cloud-specific aerial-perspective volume, or a powder darkening hack). The base sky LUTs and aerial perspective are already shipped and are not re-planned; this planset extends them.

**Dynamic sky, not a re-bake stall.** Making the sky dynamic is a scheduling problem, not a new sky model. The sun-independent Transmittance (256×64) and Multiple-Scattering (32×32) LUTs stay frozen behind an atmosphere-dirty gate; only the sun-dependent Sky-View LUT, the `atmos_skygen` env-cube fill, and the SH diffuse re-derive per sun-move (cheap, ~microseconds + ~0.015 ms), while the expensive specular prefilter (~0.8 ms) is time-sliced across ~9 frames on an async path past a sun-move threshold and *temporally blended* into the previous mips — never a hard swap that pops (Hillaire 2020; UE SkyLight Real-Time Capture TimeSlice). The synchronous `device.wait_idle` full re-bake is replaced, not kept beside the new path.

**One transmittance source of truth for sun, moon, disc, and IBL.** The scene key light is a read-out of the same atmosphere the sky uses: `L_sun = E_TOA(≈120000 lux) × T(height, sun_zenith)` from the Transmittance LUT, so the directional light, the sky, and the physically-based sun disc (0.545°, limb-darkened, `I(μ)/I(1)=1−u(1−μ)`, u≈0.6) all redden in lockstep with no authored sunset curve. The moon is a *second* atmosphere-coupled directional light — transmittance-tinted, a Hapke/Lommel-Seeliger disc with opposition surge (deliberately NOT limb-darkened like the sun), single-scatter only, ~0.26 lux full — so moonrise tints the sky correctly.

**Clouds reconcile with the existing atmosphere, they do not duplicate it.** Aerial perspective is already built. Clouds sit *beyond* the 32³ AP froxel (which spans only ~32 km against opaque depth), so they receive AP by sampling the shared Transmittance/sky-view LUTs at the cloud hit distance — NOT a second cloud-specific AP volume that would drift out of sync and seam at the horizon. `T_cloud` folds onto the one `height_fog.slang` ledger (`T_total = T_fog · T_aerial · T_cloud`, premultiplied, front-to-back), and one top-down density-integrated cloud shadow map drives cloud self-shadow, scene-mesh shadowing, and per-froxel god-rays through the *existing* fog. Camera→cloud atmosphere is applied exactly once — no double-darkening.

**Decouple the cheap dynamic-sky wins from the risky cloud raymarch.** Two roots. The dynamic-sky/time-of-day track (Phases 1–3) ships animated sky, coupled key lights, live IBL/GI, and a night sky without ever touching a cloud march. The cloud track starts in parallel with shape authoring (Phase 4, no lighting — verifiable by density visualization), then the expensive lit raymarch (Phase 5) rides the already-built motion vectors + TAA history for quarter-res temporal reconstruction, and integration (Phase 6) folds it onto the shared ledger. The marquee cost — the cloud raymarch — is isolated from the cheap wins.

**Modern-correct only, NO-LEGACY.** SH 9-coefficient diffuse (Ramamoorthi) replaces the 32² irradiance cube in the same change — the cube consumer is rewired, not left beside it. Energy-conserving multi-octave multiple scattering (Wrenninge/Frostbite) replaces the powder darkening hack. A hybrid ephemeris (NREL SPA) + elevation-indexed artist curves replaces any hand-cranked skybox spin. Each setting has exactly one write path; each superseded flow is retired in the change that supersedes it.

> **Frozen atmosphere LUTs (transmittance + multiscatter) → per-sun-move { Sky-View LUT → env-cube fill → SH diffuse } + amortized/async specular prefilter → coupled sun/moon key lights + live IBL/GI → { cloud shape → lit raymarch → temporal reconstruct } → one `(inscatter.rgb, transmittance.a)` ledger: `T_total = T_fog · T_aerial · T_cloud`, premultiplied front-to-back, camera→cloud atmosphere applied once — no double-darkening.**

## Goal

- **Dynamic time-of-day with no stall.** The sun/moon animate, the Sky-View LUT + env cube + SH diffuse reconverge per sun-move and the prefiltered specular reconverges amortized/async — the synchronous `device.wait_idle` full re-bake is gone.
- **Physically-coupled key lights.** Sun and moon color/intensity and their sky discs are read from the Transmittance LUT (one radiance shared by disc and light), giving correct sunsets and moonrise with no authored color ramp; the moon is a second atmosphere light with a Hapke disc.
- **Live sky-light IBL + GI.** SH diffuse projected per frame, prefiltered specular reconverged, and DDGI/voxel-GI sky ambient retinted from the live sky instead of a flat scene color.
- **A time-of-day driver + night sky.** An NREL-SPA-class ephemeris + artist 1D curves keyed by sun elevation, authored with a reused monotone-cubic curve widget and a scrub command; a catalog-driven night sky (stars, Milky Way, moon phase + earthshine).
- **Volumetric clouds.** Nubis-style shape authoring (Perlin-Worley + Worley erosion + curl, weather map, cloud-type gradients), an energy-conserving lit raymarch with quarter-res temporal reconstruction, integrated with aerial perspective + cloud shadows + god-rays + wind/weather animation on the one shared ledger.
- **One write path per setting.** `set-atmosphere` carries the sun/moon coupling, `set-clouds` the cloud state, a time-of-day command the driver; `CloudSettings`/time-of-day are scene state on `SceneEnvironment`, scriptable from `sa`, surfaced in the Environment panel and docs.

The chain has two roots. Phase 1 is the enabler for the whole dynamic-sky track: it turns the frozen Hillaire chain into an amortized one and couples the sun/moon key lights to it, shipping animated sunsets on its own with no clouds. Phase 2 rides Phase 1's sun-move threshold to make the sky-light IBL live (SH diffuse per frame, specular reconverged amortized) and retint GI. Phase 3 sits atop both — it drives the Phase-1 lights from an ephemeris (feeding the same re-bake gate) and needs the live IBL of Phase 2 for a believable night, then adds the physically-based night sky. Independently, Phase 4 is the cloud track's greenfield root: cloud shape with no lighting, verifiable by density visualization, touching none of the sky work. Phase 5 is the risky marquee raymarch — it needs Phase 4's density field and Phase 1's Transmittance-LUT sun/ambient, and rides the already-built motion vectors + TAA history for quarter-res reconstruction, but is deliberately isolated from the cheap Phase 1–3 wins. Phase 6 closes the loop: it needs Phase 5's marched clouds and Phase 3's time-of-day (for the wind/weather cycle and the moon that lights night clouds), and folds `T_cloud` onto the one shared ledger the fog planset already established.

## Future (unscheduled)

- **Nubis-3 sparse voxel cloud authoring.** A BC6 dimensional-profile NVDF + BC1 SDF sphere-trace up-rez with Houdini "Atlas" sourcing / Aero solver — the modern end-state for bespoke, fly-through, terrain-shadowed clouds that a procedural weather-map shape cannot express. Phase 4 leaves the density-sampler seam clean for it but ships the procedural weather-map path; the voxel authoring + import pipeline is deliberately deferred.
- **Real-time ray-traced sky GI for the moving sun's bounced indirect.** DDGI probe reconvergence treating the live sky as ray-miss radiance (Majercik 2019 / RTXGI). SH diffuse (Phase 2) retints sky-color GI but does not capture the sun's moving indirect bounce; the RT probe field is the end state when the ray budget allows.
- **Adaptive Probe Volume sky-occlusion bake for day-night GI on static geometry.** Bake sky visibility once, modulate by the live SH sky color at runtime (Unity APV) so lightmapped surfaces track time-of-day from a single bake; not built here.
- **Altitude / space-view atmosphere.** Per-pixel transmittance across large optical-depth spans and a non-zero camera altitude (currently hardcoded 0 in `AtmosPush`/`AerialParamsUbo`), for flight and orbital views; the LUT chain is authored for a ground observer today.
- **Order-independent / painted weather authoring and lightning-lit storm interiors.** Hand-painted cloud/weather maps for hero moments and an inner-glow term for superstorm interiors (Nubis Cubed), beyond the procedural weather-sim default this planset ships.

## Ground rules

- **One write path per setting.** `set-atmosphere` carries the sun/moon-coupling knobs, `set-clouds` the cloud state, a time-of-day command the driver — never a second sky command, never a knob smuggled onto an unrelated `set-environment`/`set-fog`, never a duplicate composite pass.
- **Clouds reconcile with the existing aerial-perspective and fog ledgers.** Never a second AP volume (clouds sample the shared LUTs at their hit distance), never a duplicate composite, never apply the camera→cloud atmosphere twice. `T_total = T_fog · T_aerial · T_cloud` on the one `height_fog.slang` ledger, premultiplied and front-to-back.
- **The sun, moon, disc, and sky-light IBL all read one transmittance source.** There is no authored sunset color curve decoupled from the rendered sky, and the sun disc and key light share one radiance.
- **Modern-correct, NO-LEGACY.** SH diffuse replaces the irradiance cube in the same change (no cube path left behind); energy-conserving multi-octave scatter replaces the powder hack; the amortized re-bake replaces the synchronous `device.wait_idle` full re-bake — no static path kept alive next to the dynamic one.
- **Reuse the built infra.** The 3D transient images (`acquire_image_3d`/`import_image_3d`), the `groups_z` 3D dispatch, the froxel fog, motion vectors + TAA history, and the `(inscatter, transmittance)` ledger convention — do not rebuild them for clouds; the sky LUT chain and aerial perspective are done and are not re-planned.
- **Sky, cloud, and time-of-day are scene state on `SceneEnvironment`.** Round-tripped in the project `environment` block via `environment_to_json`/`from_json` — not `RenderSettings` — mirroring how the atmosphere and fog are authored per-scene.
- **Each phase ends green.** `just engine` + `just prepare-for-commit` (format + clippy `-D warnings`), a validation-clean headless boot on the NVIDIA GPU (`just run-engine-headless`), an `sa` probe that changes the frame, `bun run check` in `editor/` where a wire type changed, `just e2e`, and the matching `docs/content/` page + its hub `_index.md` row updated in the same change.
